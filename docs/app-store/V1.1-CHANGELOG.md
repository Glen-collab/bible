## Changes since build 1.0 (2)

### The Empty Tomb scene now matches its artwork — `9b6d524`

The rail and rung coordinates were left over from an older layout, so pieces landed off
the tomb art. Pieces anchor by their **top-left corner** and span `DEFAULT_SIZE` cells,
so the on-screen center is `col + (size-1)/2`; measured against the doorway on
`assets/scenes/tomb.png` (~70% across, 60% down):

| Piece | Was | Now | Lands at |
|---|---|---|---|
| stone (sealed) | (2,1) | **(5,3)** | 72% / 63% — on the door |
| stone (open) | (0,1) | **(2,3)** | 34% / 63% — flat roll onto the path |
| jesus | (4,3) | **(5,3)** | 69% / 58% — in the doorway the stone left |
| angel | (2,2) | **(4,4)** | 53% / 71% — ground level before the mound |

`women` at (1,4) was already correct (20% / 77%) and is unchanged. The rail was kept
deliberately — the sideways roll is the story beat, rung 0's no-argument
`place("stone")` only works because the rail supplies `home`, and `open` stays on the
same row so `move("stone","left")` and the left-opens logic at `src/workshop.js:384`
still hold. Pulling `open` back to column 2 also stops the stone overlapping the risen
Jesus.

Why this mattered more than it looks: **`emptyTomb` is the only `freeBuild:false` scene
in the app.** The other ten are free play, but here Ada dictates the exact numbers and
`itemAt` (`src/workshop.js:205`) checks them with zero tolerance — so a stale target
taught a wrong spot and then said "Perfect!"

### The railed stone explains itself — `ab8fba2`

`place()` on a railed piece overrode the typed coordinates and echoed back the rail's
home position, so a kid typing `place("stone", 1, 1)` read *"stone placed at 5, 3"* with
no explanation. Now, **only** when the typed coordinates differ from home, Ada says the
stone is too heavy to lift and rolls in a carved track, and the console echo reads
*"rolled to its place on the track at 5, 3."* The guided path is untouched — rung 0 and
the `aiPreview` line pass no coordinates or the matching ones, so both still get the
plain sealed hint.

**Follow-up fix (found by testing it in the app):** the first attempt printed the console
echo but Ada stayed silent. `emptyTomb` is `freeBuild:false`, so snapping the stone home
*satisfied rung 0*, `onRungComplete()` fired, and the message was discarded unread — the
kid typed the wrong numbers and Ada said *"🎉 You did it!"*, which is worse than the
original silence. `tutorSay()` replaces the panel rather than appending, so a second call
could not fix it either. The note now rides into `onRungComplete(lead)` and is prepended
in one call. Verified: wrong coords → explanation **and** celebration; correct or absent
coords → celebration only, no spurious lecture; no stale note leaking into the next
command.

## Lesson recorded from this round

Three of these commits were live on Pages and **invisible in the browser** because
`index.html` still pinned `?v=82`. `curl` confirmed the deploy while the browser showed
old behavior — both true at once, and very easy to misread as a code bug. **Bump `?v=NN`
in the same commit as any `src/`, `data/`, or `styles/` change.** Also in
`PROJECT_STATUS.md`. Note this cannot affect the iOS app, where Capacitor bundles `www/`
into the binary.

## Release checklist

1. `git pull` and confirm the tomb scene renders correctly in a browser first.
2. Re-run the Kids-Category verification in `KIDS-CATEGORY-ANSWERS.md` — the four
   answers must still be "no" (they are, as of 2026-08-09, on current `main`).
3. Bump **both** `MARKETING_VERSION` → `1.1` and `CURRENT_PROJECT_VERSION` → `3` in
   `ios/App/App.xcodeproj/project.pbxproj` (**two places each**, the Debug and Release
   configs — lines ~357/362 and ~378/383). ASC rejects duplicate build numbers.
4. `npm run build:web && npx cap sync ios`
5. Archive, export, validate, upload — full commands in `APP_STORE.md`.
6. Create the 1.1 version in App Store Connect, attach the build, paste What's New,
   answer the Kids-Category questions again from `KIDS-CATEGORY-ANSWERS.md`, submit.

**Do not start any of this until 1.0 is approved.** Attaching a new build to the version
currently under review would abandon the in-flight submission and restart the queue.
